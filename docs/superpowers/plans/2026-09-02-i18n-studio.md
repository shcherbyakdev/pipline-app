The preview inside both pages renders in the org's language on purpose (it is what a client sees).

## Spine
- `studio.*`: widget layouts and stay layouts (label + description per value), themes, the "Latin only" font note, section labels and descriptions, the preview ghost labels, the section-frame chrome, every starter string (ICU for the price lines), the page switch.
- `embed.*`: the links-table row labels and badges. `public.embedTitle.*`: the iframe title the snippet carries onto the org's site — public copy in the org's language. `public.seed.*`: the words `newSection` seeds into a fresh document ("Book now", "Services", …) — provider content, seeded in the org's language.

## Rules that matter here
- The studio preview renders inside a nested provider in the **org** locale with only `public`/`errors`/`common` messages. Studio chrome that lives inside that subtree (section-frame chip, `Edit … section`, `· hidden`, ghost labels) takes its words as props from the admin side, so `PageRenderer` stays byte-identical for the public page.
- `WIDGET_LAYOUT_OPTIONS` / `STAY_LAYOUT_OPTIONS` / `WIDGET_THEME_OPTIONS` keep values only; components read `studio.layouts.<value>.*`. The dash rule and the no-skip rule move from `copy.test.ts` / `widget-theme.test.ts` into the messages guard.
- Zod messages in `booking-page/schema.ts` run client-side synchronously: they become keys, translated at the `issuesBySection` boundary.
- Fonts: Geist, DM Sans and Space Grotesk ship no Cyrillic subset — the picker shows "Latin only" beside them.
