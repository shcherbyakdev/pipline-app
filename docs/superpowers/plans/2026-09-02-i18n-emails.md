# i18n Wave 2 — every mail the org sends, in the org's language

**Spec:** `docs/superpowers/specs/2026-09-02-i18n-design.md` D4, §9 row 2.
**Branch:** `feat/i18n-emails`, stacked on `feat/i18n-public` (PR #106). **Status: BUILT 2026-09-02.**

## Shape

- `src/i18n/emails.ts` — `emailTranslators(orgLocale)` → `{ locale, intlLocale, t, tUnits }`, built with
  `createTranslator` + `loadMessages` (no request context: works in server actions, the reminder
  drain's route handler, scripts and tests alike). Emails follow **orgs.locale only** — never the
  visitor's region or `?lang=` (a per-booking locale is "Later" in the spec).
- `messages/*.json` `emails.*` — one key per sentence; the client's name in provider mails goes
  through `t.markup` (bold in html, plain in text). Layout untouched.
- `src/features/scheduling/templates.ts` — every builder takes `t: EmailsT` first; the staff line
  ("With Anna" / "Спеціаліст: Анна") and the badge line read messages too.
- Send sites (24): public create actions (`ctx.org.locale` / `org.locale`), manage actions
  (`getOrgLocale(booking.orgId)`), admin actions (`currentOrg()` now selects `locale`),
  `sendStaffNotice` (one `orgs` read for every kind), the reminder drain (`orgs(name, timezone, locale)`
  joined into the candidate query). When-lines take `mail.intlLocale`, money lines `mail.tUnits`.

## Verified

`npm run verify` green; integration suite green; `templates.test.ts` builds all 15 mail variants in
`uk` and refuses any English word, "запис" or "слот"; a live booking + cancellation on a `uk`
demo org read back from Mailpit in Ukrainian (client confirmation, provider copy, cancel mails).
